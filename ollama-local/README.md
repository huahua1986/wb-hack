# 本机 Ollama 性能配置与回退

只调整 Ollama 的模型清单、服务环境和缓存预热，不修改 WorkBuddy 安装包或自定义模型配置。认证和内容网关仍为 `http://127.0.0.1:8787`。

本文记录原工作区本机的配置与试验。Git 只包含工具和说明，不包含模型权重、原环境/模型快照、`evidence/ollama-local/` 或私有请求。新检出不能直接应用、回退或预热；需先在目标机器重新建立基线和匹配前缀。Dock 入口不自动执行本节预热。

当前默认 `qwen3.8:27b` 保留原 Q8 权重，设置 64K 上下文和原有 512 输入批次。原清单保存在 `qwen3.8:27b-q8-original-20261013`。Q4_K_M 测试副本为 `qwen3.8:27b-q4-workbuddy`，未作为默认模型。

## 2026-10-13 实测结果

原版 WorkBuddy 新建两个任务，发送与原对话相同的“你好”，界面完成时间分别为 **2m55s、2m17s**。这两次为顺序客户端验收，不能拿第二次时间直接证明并发排队消失。两次完整输入均为 30,994 token，实际只重算 2,790 token，模型输入处理分别为 **47.36s、47.41s**。原来的两次历史记录是 33,202/30,994 token，处理输入耗时 419.16s/372.83s。

另将本轮捕获的两份完整请求固定哈希，按 **50 秒间隔**复放以验证排队。原 Q8 预热后结果：

| 分项 | 请求一 | 请求二 |
|---|---:|---:|
| 完整输入 token | 30,994 | 30,994 |
| 缓存 token | 28,208 | 28,204 |
| 输入处理 | 39.70s | 40.47s |
| 排队及其他非模型执行时间 | 0.09s | 161.62s |
| 生成输出 | 171.80s | 134.02s |
| 总请求时间 | 211.58s | 336.11s |

历史第二次排队估计为 408.92s，本轮约 161.62s。历史请求体未完整留存，因此旧总时长只能作为历史参考；严格输入一致的验证使用本轮重新捕获并固定的完整请求。相同请求一在中间 Q8 KV 候选测试中输入处理耗时 453.52s，该候选已撤回。输出长度会随采样变化，本轮两条分别生成 1,155/886 token，不把总耗时差全部归因于硬件加速。

**冷预热成本独立计量为 343.86s（约 5m44s），包括模型加载；预热不是免费计算。** 原 Q8 当前运行占用约 34.4GB，之前为约 48.3GB。首次冷处理仍需数分钟，收益体现在后续复用匹配前缀。

Q4 的共享前缀冷处理为 76.43 token/s，原 Q8 同前缀为 84.22 token/s；这两套候选的批次参数不同，不能单独归因于量化。Q4 生成约 8.9 token/s，Q8 约 6.6～6.7 token/s。Q4 没有显示出冷长输入加速，因此默认保留原 Q8。两种权重的算术 JSON 和中文信息提取均为 **2/2 通过**，不是完整业务质量验收。

当前版本对 qwen35 架构强制单槽，`OLLAMA_NUM_PARALLEL=2` 无效；没有绕过这项保护。后台标题生成还会占用约 34～36 秒，优化后模型思考输出和这些串行请求仍会产生等待。

详见 `evidence/ollama-local/final-acceptance.json`、`native-client-metrics.json`、`q8-primed-pair.json`、`q4-primed-pair.json` 及 `client/` 中的截图。API 返回的 `prompt_per_second` 用完整逻辑输入计数，包含缓存 token，不能把该数当作实际 GPU 重算速度。

64K 能容纳本轮约 31K～33K 输入，没有截断本轮测试。未来超过 64K 的任务需要重新评估上下文配置。F16 KV 保留；Q8 KV 在这台机器上的实测更慢，已撤回。服务驻留设置为 30 分钟。`launchctl` 环境只对新启动的 Ollama 生效，在重新登录 macOS 后需要再次应用环境并重启 Ollama；每个模型的 64K 清单参数保存在模型库中。

预热请求也明确传入 `keep_alive: 30m`。当前版本后续没有显式驻留参数的请求会沿用已加载模型的驻留时长。完整退出或重启服务仍会清空运行时缓存。

## 启动

本次优化已在当前 Ollama 实例生效。以后完整退出 WorkBuddy，双击工作区的 `预热模型并启动WorkBuddy.command`，它会计算稳定前缀，再调用原有启动器。第一次冷预热需要数分钟，后续命中缓存时会更快。预热成本与聊天耗时分别记录。

稳定前缀来自原版客户端生成的完整请求，保存在 `evidence/ollama-local/private/`，权限受限。它未删除工作目录、时间、工具定义等上下文；实际聊天仍提交完整输入。这个模型的混合状态不能任意切回共享前缀，需要在变化位置之前建立检查点。预热在该位置之前创建检查点，从而让后续不同任务复用稳定部分。该优化只对匹配此前缀的请求有效；模型卸载、服务器重启或提示词较早部分变化后需要重新预热。WorkBuddy 升级后脚本会拒绝使用旧前缀，应重新采集并验证。

## 回退

保持本机 Ollama 运行，双击 `回退Ollama优化.command`，然后完整退出并重新启动 Ollama。脚本恢复原模型清单及原环境值，不删除模型、对话或缓存文件。如果用户之后自行改了相关模型或环境，脚本会拒绝覆盖。

再次启用可运行 `应用Ollama优化.command`，然后重启 Ollama，再使用预热启动器。

## 验证边界

完整原始请求仅保存在本机，临时记录通道已在测试后移除。模型访问恢复为直接 `localhost:11434`。

Q4 从已有 Q8 重量化得到，并保留输出张量。两项算术与中文 JSON 提取校验只能检查基础正确性，不能证明业务任务的整体质量与原模型相同。五分钟 HTTP 超时以及诊断字段错误导致的试验不计为成功成绩；有效成绩以 JSON 中 `status=200`、`finishReason=stop` 和模型运行时计时为准。
