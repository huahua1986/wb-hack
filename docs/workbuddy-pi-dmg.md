## 通用实现与 0.1.1 边界

候选主入口在原版主程序前初始化独立目录，清除继承的私有认证端点及产品配置覆盖，注册 Pi Host，再运行保留的原版界面和官方认证。Pi Host 通过进程内 `webContents.debugger` 投影线程、流式正文、工具、审批和取消；不开放调试 TCP 端口。

精确版本补丁移除 `cli/bin`、`cli/dist`、`cli/node_modules`、`node_modules/@genie/agent-harness`，并阻止原生预热、session 初始化、ACP/PATH 回退和隐藏 SDK 加载。保留原产品配置、vendor、安全组件、扩展和许可证，因此保留 `cli/` 目录不意味着仍带 CodeBuddy 执行器。ASAR header 校验、Electron Fuse 和必要签名要求保留。

Pi-only 模式确认官方 `wb.account.status()` 为 `authenticated` 后再接管会话；登录弹窗后的底层 DOM 不能作为登录完成证据。原生首页输入依赖原生模型服务，因此新任务先打开真实 Pi controller，不强行启用原生发送按钮，也不伪造模型或授权结果。

受控审批扩展在每次 `edit`、`write`、`bash` 前等待 Host 的单次确认。扩展缺失、内容哈希不匹配、未知确认协议、审批超时或传输失败均拒绝执行。`read`、`grep`、`find`、`ls` 为只读工具；这不是操作系统级文件沙箱。项目提示、全局扩展、MCP、skills、上下文文件和提示模板自动发现关闭。

目前只接入文本及上述 Pi 工具。图片、附件、工作台技能、乐享材料到 Pi、原生 MCP/权限策略、检查点和回退等未宣称兼容；缺失操作明确拒绝，不回退已移除的原生 CLI。官方账号授权不会自动变成 Pi 模型或工具凭据。
