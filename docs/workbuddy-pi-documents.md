# 金融buddy 0.4.4：本地文档解析

## 使用方式与范围

在原生对话框通过附件按钮或 `@文件` 选择本地文件，再发送问题。PDF、DOCX、XLSX、PPTX 会先在本机提取文字，随后进入 Pi 的同一条用户消息，使用当前选择的模型回答。保留 WorkBuddy 5.9.2 原生界面、Pi 1.4.0、金色图标、官方登录、上下文档位及既有自动执行设置；原版 `/Applications/WorkBuddy.app` 不修改。

| 格式 | 提取内容 | 限制 |
| --- | --- | --- |
| PDF | 文字层、页码；没有文字层的页面用本机 Vision OCR | 最多200页。OCR可能识别错字；不重建复杂表格或版面，不读取批注和附件，已有文字层页面内的图片不另做OCR |
| DOCX | 正文、段落、表格文字、页眉页脚、脚注尾注 | 不识别文档中的图片、图表、公式对象与嵌入文件；不保留排版 |
| XLSX | 按工作簿次序读取工作表、单元格地址、共享/内联文本、原始值与公式缓存结果 | 不执行公式，不刷新外链，不重建日期/货币显示格式；无缓存公式明确标记；包含隐藏工作表并标记 |
| PPTX | 按演示顺序读取幻灯片文字、表格文字、备注 | 不识别图片或图表，不重建空间布局 |

DOC/XLS/PPT、ODT/ODS/ODP 暂未支持，需另存为上述格式。加密、禁止复制或损坏的文档明确报错。只有本地已完成选择的文件可读取；网盘、乐享等远端资源仍需先下载。文字总量仍受模型上下文预算约束。

文档上限为单文件25MiB、每轮文档合计64MiB；单文档文字512KiB、整轮用户文字1MiB、最多16个附件。图片和原UTF-8文本仍沿用合计4MiB及单文本512KiB的限制。Office ZIP最多10000项，单XML最多8MiB、实际读取XML合计32MiB；PDF解析/OCR120秒，Office15秒。超限报错，不静默截断。

## 实现与数据边界

原生输入组件只传所选路径与元数据。`turn-input.mjs` 继续校验本地路径、普通文件、符号链接、选择时大小以及读取前后的文件身份和时间戳，读取后将同一份不可变字节交给解析器，不重新打开用户路径。

PDF在单独的Swift进程中用Apple PDFKit和Vision提取，OCR在本机执行。Office在有内存限制的Node Worker中用yauzl读取ZIP、saxes解析XML；依据内容类型和relationship定位正文、工作表及幻灯片。没有解压落盘，不获取外部链接，不执行宏、PDF脚本、公式或内嵌对象。ZIP路径、符号链接、重复项、CRC、解压后大小和XML DTD均有检查。取消或超时终止本轮持有的解析进程/Worker，失败不会向Pi发送半份附件。

提取文字作为“用户附件文档”放进实际模型输入，解析警示随文字一起提供。Host的`threads.json`只保存文件名、来源、SHA-256、原大小、格式、页/表/幻灯片数量和提取字节数等元数据。**Pi会话仍会保存实际模型上下文，包含提取的文档文字，应按敏感会话管理。** 本地解析不增加额外解析服务；发送问题时，提取文字仍会发给用户所选的模型，当前独立版本通过既有官方模型桥访问。

解析依赖独立放在应用`Contents/Resources/DocumentEngine`，包含锁定ZIP/XML依赖与许可证、编译好的PDF助手。客户无需安装Python、Office、编译器、Node或Pi。构建器固定完整依赖树与锁文件哈希，编译Swift源码后对同一候选签名并记录PDF二进制哈希，封装不重新签名。

## 维护与回退

开发依赖准备、来源链接与单测方法见[DocumentEngine说明](../pi-harness/document-engine/README.md)。主构建命令仍是[5.9.2升级说明](workbuddy-pi-592-upgrade.md)中的`--source-app`流程，使用新输出目录`dist/金融buddy-5.9.2-test-0.4.4`；不能从旧Pi包伪装原版源构建。PDF/OCR需正常macOS本机服务，限制XPC的测试沙箱可能无法运行Vision。

升级应先正常退出旧版，在没有运行任务时备份独立状态与应用，再替换安装；不迁移原版账号，不重放业务任务。回退可正常退出后恢复旧应用，Pi数据目录保持兼容。0.4.4仍是ad hoc签名、未公证的内部候选，正式分发需组织授权、正式签名和公证。
