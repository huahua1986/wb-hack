# 金融buddy 0.4.11：专家加载修复

本版基于固定来源的 WorkBuddy 5.9.2、Pi 1.4.0，修复 Pi 版加载已安装专家后不能创建任务的问题。原版 WorkBuddy.app 不改，官方登录、模型桥、原生页面和执行权限保持既有行为。

## 原因与修复

本机失败发生在 Pi 执行前：原生日志返回 `Expert not found: SeniorDeveloper`。选择对象具有 marketExpertId、source、runtimeIdentity 和已安装的 senior-developer 专家包，而旧适配只向解析器传递 id/marketplace，并强制重新取云端正文。原版创建参数实际位于完整的 `params.expert`，且可使用已安装的本地运行身份；旧适配没有保持这一契约。

修复保留完整的原生专家身份，runtimeIdentity 按不透明字符串原样传递。Host 在固定的独立配置根下读取专家映射、安装包 manifest 和声明的 agent Markdown，把主指令及包声明的渐进技能目录交给 Pi。无法确定本地包时仍使用原生查询；官方/企业身份不会被同名本地自定义专家替代，也不会把默认开场白当作专家指令。解析失败明确阻止发送，不静默降级为普通对话。

云端查询的 Not found 包装也可能遮蔽网络或正文加载错误。本次没有用真实账号重新查询该专家云端接口，因此不将该日志认定为官方目录已下架。修复依据是已确认的身份丢失和本地包读取缺口。

## 支持与边界

- 支持已安装、manifest 声明明确、可唯一选择的单 agent Markdown，以及原有指令型专家。
- 包内技能只提供名称、描述、路径和运行要求提示，正文由模型按需用现有工具读取。不会自动加载脚本、扩展或扩大工具权限。
- 现有 MCP 和自动/手动执行策略保留。插件级 MCP、Hook、多 agent 编排或未映射的 agent 运行配置明确拒绝，不声称支持整套 CodeBuddy 插件运行时。
- 绑定、发送及重启后发送会核对包版本、manifest/agent/skill 哈希；删除或更新后需要重新选择专家。
- 只在可信配置目录的安装包内读取。拒绝越界、符号链接、硬链接、身份冲突、非法 UTF-8、读取竞争和超限文件。manifest 64KiB、agent 24KiB、单技能128KiB、合计512KiB、最多8项技能；只可收紧。
- 清除专家会移除后续轮次的专家指令；历史上下文照常保留，不回写或重跑已有任务。
