# 金融buddy 0.3.1：上下文占用圆环

0.3.0 的原生输入框圆环会提示“暂时无法获取用量明细，请稍后重试”。这是当前会话上下文详情入口，不是账号余额、积分或计费入口。原生组件依赖 `refreshContextUsage()`、`contextUsageChanged` 及五类明细；0.3.0 仅保存了 Pi token 用量，该刷新方法没有接通。

## 修复语义

0.3.1 使用 Pi 1.1 的 `get_session_stats.contextUsage`，显示 **Pi 当前上下文估算**和 Pi 配置的上下文窗口。它与 Pi 自身的压缩/上下文预算采用同源数据：最后一条有效模型用量，加上后续消息的估算；压缩后没有有效基线时允许为空。这个值不等于当前轮累计 token，也不等于全会话累计 token。

真实 token 用量继续保存于 `turn.usage` 和原生适配请求的 `piTokenUsage`，不再把它投影成原生消息的上下文占用。用量摘要经 `contextUsageChanged` 进入原生圆环，重启打开旧会话时重放已保存摘要并刷新。

Pi 不提供原版的系统指令、工具、对话消息、MCP、技能五类准确拆分。因此不构造 `byCategory.version=1`，不把缺失字段填零，也不把总量全算进“对话消息”。只在当前 Pi 对话中适配原生专用 tooltip 的文字，说明总量属于估算、配置窗口及“原生分类明细暂不支持”；保留原环、布局、焦点和原版界面资源。忙碌会话及非 Pi 页面保留原提示。

原生组件在分类缺失时成功刷新会继续等待 15 秒。适配器先完成总量事件刷新，再按原生错误合同返回“分类不支持”，让原生加载状态立即结束；这不是模型请求失败，不影响会话执行。

## 只读刷新

已有 Pi 进程时查询它的统计。旧会话没有运行进程时，在私有目录创建会话快照，用内置 Node/Pi 打开副本，关闭自动扩展、MCP、技能及工具，只发送 `get_state`、`get_session_stats`，随后关闭并清理副本。官方 Provider 只读取本机模型目录，统计过程不调用模型。

刷新合并并发请求，不改变任务活动时间。模型或轮次改变时，旧查询结果不能覆盖新状态。读取失败保留有限诊断码，不存 stderr、凭据或消息正文；未知值保持未知，不显示为零。冷查询不会重写原会话。

- Pi 官方 SDK 原样消费者与原生 5.9.1 UI 消费者的独立 fixture 验证通过；原生分类无法表达未知、累计用量覆盖圆环及加载状态行为均有重放测试。
- 本地回归 315 项：311 通过，4 项为条件测试（三项真实 Pi 协议另跑，一项要求本机存在原版 5.9.1）。包括总量与累计分离、并发刷新、快照清理、tooltip 范围和恢复、原界面 DOM 保持及原生事件合同。
- 真实 Pi 离线测试确认当前上下文 **85** 与全会话累计 **1,315** 分离；删除旧记录的摘要后可只读恢复 **85/32768**，模型调用次数不增加、MCP 调用为零，原会话逐字节不变，私有快照清理完成。
- 本机原版已升级至 5.9.2，不作为 5.9.1 构建源。0.3.1 从受 SHA-256、签名、完整 PiEngine 和原生界面指纹约束的已验收 0.3.0 增量生成，不修改旧包或已安装版本。

2026-10-26 已完成同一冻结候选的只读 GUI 验收：原生圆环提示显示 **2,728 / 配置窗口 32,768 tokens（8.3%）**，同轮累计 token 为 **5,453**，两种口径分离。文字在原 240px 提示框内正常换行，没有改写原生页面布局；切到专家页面无 Pi 用量提示。

再次刷新和完整退出重启后，原会话 JSONL 哈希一致，临时统计目录为零；本机模型桥的完成请求及活动请求均为零。无需重新登录，模型选择和旧会话恢复，圆环仍能直接显示同样统计。验收期间 31 项构建源码、27 个部署 Harness 文件未变，原生 1,958 个 renderer 文件与 0.3.0 一致。
