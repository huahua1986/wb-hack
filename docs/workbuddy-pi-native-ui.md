0.3.0 在此模式上继续实现附件、Expert、技能和 MCP；最新功能范围及验证状态见[原生内容映射](workbuddy-pi-native-content.md)。本页保留 0.2.8 的原生界面与历史验收证据。

0.2.6 把“只用 Pi 执行”与“全局接管界面”合在 `exclusive` 模式：跳过首页、过滤原任务列表、显示 Pi 徽章、替换模型菜单、隐藏附件和权限等控件。0.2.7 将 UI 范围拆为独立的 `nativeUi` 模式，保留原组件，只在会话服务边界接入 Pi。

本机候选位于 `dist/金融buddy-5.9.1-test-0.2.8/staging/金融buddy.app`。已完成源码、合同测试、构建、签名和同一候选实机验收：原生首页发送、Hy4 对话、单次工具审批、停止、导航与完整退出恢复通过。最终 DMG 尺寸、校验和及限制见[安装包说明](workbuddy-pi-dmg.md)。

## 为什么无需改造原版模型菜单

核对 5.9.1 源码后，正常原生 `adapter.getModels()` 优先读取 daemon 产品配置，只有没有该客户端时才回退旧 session API；目录 `pending` 时有意返回空数组。首页输入还受草稿、创建状态、模型权限等业务条件控制，不能归结为“缺少 CLI，所以必须跳过首页”。

首页 `conversations.create()` 已传 `model/cwd/title`，之后暂存首条消息再导航。会话页面先 `controller.start()`，再从原 `ui.input.sendPrompt` 发送。适配器因此需要原子应用初始模型，并尊重发送意图里的 `modelId`，而不是强行启用发送按钮或替换输入框。

原生模型目录不依赖虚构的 `controller.models` 属性。选中模型通过现有 `configManager.model/setModel` 和 `{conversationId,models,currentModel}` 事件同步。

## 数据与执行边界

`exclusive:true` 继续表示新本地对话只用 Pi；`nativeUi:true` 关闭原先全局界面接管。品牌、认证、模型、历史状态保留于既有独立目录，不修改 `/Applications/WorkBuddy.app`。

本地列表保留原查询家族、置顶及活动时间排序，先取原生所需前缀再合并切页；`independentTotal` 只统计自动工作区根任务。还按原 `on('listChange', (space,snapshot,traceId))` 合同增强本地权威快照，并以 trace 对应原 `ensureList` 过滤条件，避免乐观追加后被原快照覆盖。模型目录刷新不再刷新任务活动时间。

原生本地历史的 `get/requestEntries` 默认走 metadata/JSONL，不需 CLI，但输入意图会调用 `ensureRuntime`。因此旧历史使用只读 facade：已证实的历史读取和事件可用，运行、前台执行及未知执行入口阻断。旧云历史及其他未确认的会话类型明确提示未接入，不暗中启动原执行器。

界面保留不代表全部能力已经映射到 Pi。附件、Expert、原生技能/MCP、分享/检查点/回退、云执行及原生 OS 沙箱等仍有未适配范围；非文本发送、未映射的 Expert/MCP/完全访问选择明确拒绝，不能表现为成功但实际未使用。Pi 写入、编辑和 Bash 保持逐次确认。原生默认权限 UI 仍保留，Pi 不宣称具备原生沙箱。
