# 无外网环境的运行与验收

客户网络没有外网出口时，使用网络侧已有隔离即可。客户端不安装防火墙、TUN、网络扩展或新的启动 App；原版 WorkBuddy、私有认证网关与自定义模型直连关系不变。本轮取消的防火墙草稿从未启用，不进入代码提交和交付包。

外网断开时，私有认证服务仍须可达。本机部署需要先启动 http://127.0.0.1:8787，内网部署使用可达且证书受信任的 HTTPS 入口。启动器会检查网关健康，不能把后端也不可达的情况当作可长期离线登录。账号与刷新令牌依然由私有服务校验，撤销和单账号单会话策略继续有效。

模型服务及权重也应位于本机或内网。本轮选用 qwen3.8:27b，通过 http://localhost:11434/v1/chat/completions 调用 Ollama，没有经过认证网关。已有其他外部自定义模型配置保留；它们在隔离网中不具备可用性保证。

## 本轮修复

- 5.8.3 已安装技能查询会在缺少市场 ID 时使用技能名称。实机一批 27 个查询键中有 1 个中文名称，原服务把整批拒绝，诊断时累计 4012 次 400。后端现在接受有界的 Unicode 查询键，未发布或不可见内容仍返回空结果；查询键不作为文件路径，也不产生付费权益。类型、数量、路径和控制字符限制保留。
- 原版持续推送插件资源变化，并触发技能元数据查询。外部运行时适配只合并 `skill:versionChanged`、`skillsVersionChanged`、`plugin:changed` 通知，每个通道在 500ms 窗口内保留最新值。认证事件、模型流、对话消息与其他事件直接通过；导航和退出会清理定时器。这是下游合并，没有修改原版通知源。
- 启动器判断独立实例时识别同一主进程的子进程，避免将自己的 Electron sidecar 当作另一实例。真正独立运行的实例依然受到保护。
- 对关闭的云助理会话与已发布助理两个只读目录，按 5.8.3 消费端结构返回经认证的空列表，减少启动时 404 重试。分页参数仍校验，写操作和其他未知接口仍报错，不伪造上传、保存、云任务或模型调用成功。

## 本机验收条件与结果

本轮在 macOS arm64、原版 WorkBuddy 5.8.3 上完成两轮**进程内网络故障注入验收**。外部 HTTP/Socket 请求被注入不可达错误，Chromium 外部请求被取消；本机环回及 IPv4 私有地址继续访问；本次认证和模型服务均使用环回地址，未测试跨机内网、内网域名或 IPv6 模型服务。本机系统代理端口不会成为测试进程的外网绕过通道。第一轮立即失败，第二轮外部请求延迟 1500ms 后失败。没有更改系统网络、代理、路由、证书或其他应用的连接。

该方法验证应用应对外部请求失败的行为，不是全机物理断网，也不是安全出站防火墙。非 Node 外部工具、DNS、路由、客户内网 TLS 等需现场验证，不能仅凭这些结果宣称客户隔离网验收完成。早期 sandbox-exec 尝试额外阻断了 setuid ps，并与 Chromium 沙箱冲突；这些失败不计为有效断网结果，测试进程已清理，原登录入口已恢复。没有通过关闭 Chromium 沙箱完成测试。

完整回归 112 项通过，无跳过。已确认：

- 外部请求失败时，冷启动、两处企业名称、私有账号恢复正常；账号查询及 refresh 返回 HTTP 200，没有手动重新登录或重新加载。
- 完整退出后，再次冷启动恢复了测试会话及已有历史，仍可选择本地 qwen3.8:27b。
- 第一轮实际回复“离线模型可用”，界面耗时 7m12s。Ollama 主请求 HTTP 200，提示词处理 30670 token 耗时约 371.6s，长等待主要在本地长输入处理，不是私有登录或外网认证。
- 重启后续聊实际回复“恢复后模型可用”，界面约 40s；Ollama HTTP 200 约 39.4s，提示词实际重新处理 2146 token、约 31.3s。本轮未改模型权重或 Ollama 参数，不把缓存表现归因于本轮修复。
- 同一原版进程树中的后台进程实际连接 127.0.0.1:11434；认证网关没有接收到模型推理请求。已有 models.json 保留。
- 修复 Unicode 查询后，400 消失；加入通知合并后，观察窗口内技能查询从 2923/46.3s（约 63 次/秒）降至 39/21.1s（约 1.85 次/秒）。观察窗口不同，这不是完整性能基准。

现场记录在 `evidence/offline-acceptance/`，包含脱敏界面记录、路由计数、原包/模型配置哈希、运行器耗时和失败尝试；不进入 Git 或交付包。认证数据库和分发密钥在修改前已备份，未通过更换账号库完成恢复。

## 开发机复现故障注入

以下仅用于验收，不作为客户日常启动入口；脚本不会进入客户端 payload。需要工作区源码、已安装的本项目用户级组件、兼容原版 WorkBuddy，以及已启动的私有网关和 Ollama。

1. 正常退出 WorkBuddy，暂停本项目登录任务，防止正常监听器与验收入口竞争。
2. 在仓库根目录使用 Node 24+ 运行下列命令，`--delay 0` 为立即失败，`--delay 1500` 为延迟失败；不会停止其他应用网络。

```sh
node scripts/offline-validation/launch.mjs \
  --payload "dist/WorkBuddy-client-0.1.2/WorkBuddy企业配置/payload" --delay 1500
```

3. 在原版界面确认账号、产品名称和本地模型选择；发送简短验收问题并等待真实答案，记录网关及模型服务的成功请求。不要把建立 TCP 连接或“等待模型响应”算作成功。
4. 完整退出测试实例，再恢复本项目原登录任务。测试注入只存在于该次进程中，退出后消失。不要在测试实例运行时直接认为恢复登录任务已经移除了注入。

本机用户级登录任务为 `~/Library/LaunchAgents/local.workbuddy.enterprise-client.login.plist`；用 launchctl 的 bootout/bootstrap 对本项目标签操作，勿停止其他服务。恢复之前确认路径仍属于本项目。生产安装流程不读取测试配置，不加载上述 preload。

## 客户隔离网现场验收

1. 由网络管理员确认外网出口已隔离，保留认证、模型、私有目录/安装包及内网 DNS。确认私有 HTTPS 证书链在无外网时有效；原版应用和需要的运行时、模型权重已预置。
2. 保持私有网关运行，点击原版 WorkBuddy 图标，核对企业名称和账号；完整退出后重复，确认没有额外登录、重载或新会话占位。
3. 调用选定的本地/内网模型，记录完整答案及模型端 HTTP 成功；核对认证服务没有代理推理。分别记录冷输入与续聊耗时，不能用本机 7m12s/40s 作为客户容量承诺。
4. 读取本地文件、目录及已发布私有内容；未配置的云写功能应明确不可用。观察 400/404、超时和重复请求，而非把所有错误统一改成 200。
5. 测试管理员释放会话后的失效提示与重新登录；认证后端也不可达时应明确失败，不能回退腾讯认证或无认证访问。

本轮未执行真实客户网络验收、整机重启、干净新机或系统级 PKG 安装。测试包未正式签名公证，其他 WorkBuddy 版本仍须重新确认哈希与协议。
