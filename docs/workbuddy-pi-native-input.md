# 金融buddy 0.4.10：原生输入分类

本版修复原生长粘贴文本和场景标记被当成本地附件的问题，保留远端资源、路径和文件校验；不自动展开业务链接，不改变已授权工具，不重新执行历史失败任务。基于固定来源的 WorkBuddy 5.9.2 / Pi 1.4.0，沿用0.4.9原生界面、预览、Diff和回退实现。

## 确认的协议缺口

直接新任务的普通粘贴有一条独立资源路径：`withPaste`默认把超过3000个grapheme的纯文本折叠成`longtext://<编码预览>-<字素数>`，全文位于`_meta.fullText`，`mentionType='long-text'`。字素数排除U+200B，组合字符和emoji不能按UTF-16长度替代。URI只包含短预览引用，不能反解为完整正文。旧Renderer丢弃`fullText`，Host又按非本地附件URI拒绝；对冻结0.4.9模块使用原样粘贴函数和合成正文，已复现`ATTACHMENT_REMOTE_UNSUPPORTED`。

0.4.10按原位置将完整`fullText`映射为用户文本，不计作附件，不读取任何文件或URL。引用保持opaque，允许正文编辑后仍沿用旧引用；不会用预览覆盖或补造正文。仍受整个Renderer请求55KiB及Host消息预算约束，超限明确提示使用本地TXT附件，不能把解析器1MiB上限当作GUI粘贴容量。

另外，原生首页的显式场景/deeplink/Buddy选择路径通过`composeEmbedHomeBlocks`及`applyEmbedSceneBlocks`前置`createHomeSceneBlock`资源。普通新任务的默认work分类并不自动选择企业微信场景。企业微信场景的实际形态为：

```json
{"type":"resource_link","uri":"scene://122844","_meta":{"type":"scene","mentionType":"scene","sceneId":"122844","displayText":"企业微信"}}
```

它没有附件文件路径、MIME或大小。旧0.4.9的Renderer没有保留`sceneId/displayText`，Host又把该块交给本地附件路径分支，也会触发同一错误。对冻结0.4.9模块使用原样首页生成器和纯合成文本，已独立复现该兼容性缺口；没有启动业务任务。

用户已确认是直接新建任务，从网页或文档复制粘贴，不能把原失败归因到手动企业微信入口。历史失败回合的原始输入块未持久化，当前不能声称其具体URI已恢复，也不能只凭“粘贴”断定必然是长粘贴。现有记录直接证明输入准备阶段约17毫秒失败、没有Pi会话和工具结果。短纯文本（含@人名）不自动构造资源；自定义剪贴板MIME和HTML则可能保留已有URI。空白sortable与BOM不能证明资源类型。CUA提取通道未成功，临时诊断页和服务器已关闭；用户随后授权的一次系统只读解析也未取得可核对的原生格式（format=none、消息指纹未匹配），未保存正文或再次读取。原始业务任务没有重发。

## 分类与映射

| 输入 | 本版行为 |
| --- | --- |
| `longtext://`且显式long-text元数据完整 | 从`fullText`取完整正文，按原位置拼接为用户文本；不从URI反解正文，不占附件数 |
| 长文本缺正文、协议伪装或格式/预算非法 | 明确拒绝，不把预览当全文，不访问资源地址 |
| `scene://`且原生scene元数据一致 | 校验id、名称和URI，映射为用户场景分类上下文；不计为附件，不读取文件，不授予连接器权限 |
| 场景协议/元数据不一致、混淆或多场景冲突 | 明确拒绝，不退回普通附件或技能分支 |
| `skill://`或带skill元数据的`command://` | 继续从原生已安装技能目录解析及校验SKILL.md；场景与技能可并存 |
| 显式文本选区 | 继续使用用户已选文本，按现有限制处理，不因URI去下载内容 |
| 本地图片、文本、PDF/Office | 原有本地路径、host、穿越、符号链接、MIME和大小校验不变 |
| 普通HTTPS等远端附件 | 仍为`ATTACHMENT_REMOTE_UNSUPPORTED`，不下载、不读取metadata伪装的本地路径 |
| 原生连接器链接待授权/已解析标记 | 保留受控kind并给出`NATIVE_CONNECTOR_LINK_AUTH_REQUIRED`或`NATIVE_CONNECTOR_LINK_UNSUPPORTED`，不再误称本地文件；链接内容展开仍需单独适配 |

场景id只允许有界ASCII标识，URI必须与`sceneId`完全匹配，禁止query/hash/路径等变体；名称受UTF-8长度和控制字符约束。Renderer只为已声明的长文本保留正文、为场景保留分类字段；SVG、rawUrl、auth、token等额外元数据不转发。场景只是任务分类，既不选择新MCP，也不绕过原有工具授权。只有场景、没有任务文本/附件的输入会拒绝。

## 可定位的私有诊断

新Host回合在准备输入前保存`inputDiagnostics`：最多64块，只含索引、固定类型/协议枚举、分类、短SHA-256指纹和已验证的场景id。未知协议不会原样保存，避免把用户自造协议名当作诊断文本泄漏。该字段不含正文、场景名称、完整URL、路径或凭据。

成功解析的场景另作为正常会话上下文保存在`inputContexts.scenes`，Pi用户消息中包含相同分类信息；重启可恢复。正常会话仍按现有方式保存聊天记录，不把“诊断不存正文”解释为“不保存聊天内容”。历史回合不补造诊断，不自动重试。

主要实现为`src/native-input-resources.mjs`、`src/turn-input.mjs`、`src/pi-harness.mjs`和`src/renderer/source.js`。
